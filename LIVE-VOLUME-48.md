## Fix
A separate live Delta public candlestick_5m WebSocket warning path is mounted prominently within Crypto → Setups → Early Rally Radar. Existing Start continuous scan and Pause radar control it, with existing saved opt-in. No broker login or keys used. The top20 confirmation/qualification rules remain intact; this warning is independent.

Universe: ALL returned Delta USD perpetual contracts, including low-turnover names, refreshed every10minutes. Outside top20 is included. The universe becoming >15minutes old blocks warnings. No turnover cutoff can silently exclude a newly active coin. Baselines load in turnover order. Thin markets can generate noisy warnings; this is not token safety verification. Broad universe initial historical baseline downloads are bounded3requests per2s tick; partial coverage and ready/total count stay visible. Missing/gapped history cannot qualify. Failed baselines retry without monopolising the batch.

Trigger: while the5m traded-price candle is forming, its actual accumulated volume≥3x preceding20 complete5m candle average, absolute open-to-current price move≥1%, price beyond previous20-bar high/low, and close in the directional outer quarter of its range. Both upside/downside. No elapsed-time volume extrapolation; no OI/funding warm-up, hourly close, retest or fundamental review required. Last source message≤15s old, notfuture; currentcandle time, OHLCV, historycontinuity and monotoniccumulativevolume checked. No zero-baseline ratios invented. Delta mark candles lack volume; only traded-price candles used. Stream protocol and cst/ts microsecond fields verified against a real HYPE public subscription.

Titles are bold, title-only, include coin/direction/move/ratio/ISTsecond/FORMING. They mean unusual activity, never an executable order or confirmed safe entry. One percoin/direction30minutes; duplicatecandle/updates and reconnect/restart replays suppressed. Local history is bounded40 and serialised into owner-scoped SQLite; browser-only history is bounded40 in that browser. Historical warnings are labelled after10minutes. No retrospective alerts are generated from seeding old candles.

Local server: independent WebSocket collector runs while terminal/server alive andPCawake, including browserclosed. GET /api/impulse is owner-gated read-only status; it cannot accept client signals or place orders. Browser displays saved server alerts on2s refresh whileopen. Pause stops collector immediately; late replies/baseline fetches/messages are rejected. Existing failed slow scan does not stop independent fast collector. Hosted site: same publicWebSocket engine runs in the owner's open browser. Closing/throttling/suspending it can miss events. NO always-running hostedcollector provisioned and NO newWhatsApp delivery path. Public-feed/network latency cannot be zero or guaranteed.

UI shows live/connecting/paused/error, sourceage andbaselinecoverage. It refuses LIVE on stale messages. Reconnect uses backoff and35s watchdog. Context/qualification checks and liquidationwarmup remain separate.
